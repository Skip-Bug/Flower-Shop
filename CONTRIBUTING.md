# Как работать с кодом

## Ветки

`main` защищена — прямой push запрещён. Любая работа идёт через ветку:

- `feature/<короткое-имя>` — новая функциональность
- `fix/<короткое-имя>` — исправление бага
- `chore/<короткое-имя>` — инфраструктура, зависимости

Пример: `feature/catalog-models`

## Коммиты

Формат: `тип: короткое описание` в нижнем регистре.

Типы:

- `feat:` — новая функциональность
- `fix:` — исправление
- `chore:` — зависимости, конфиги, CI
- `docs:` — документация
- `refactor:` — без изменения поведения

Примеры:

```
feat: add bouquet list view
fix: correct delivery slot calculation
chore: bump ruff to 0.17.3
```

## Установка
Для работы установите пакет зависимостей для разработчиков
```bash
pip install -r requirements-dev.txt
```
Установите pre-commit хуки:

```bash
pre-commit install
```

## Перед коммитом

`pre-commit` запускается автоматически при `git commit`. Если хук упал — исправить и закоммитить снова. **Не использовать `--no-verify`.**

Проверить всё вручную заранее:

```bash
pre-commit run --all-files
```

## Pull Request

1. Запушить ветку: `git push -u origin feature/...`
2. Открыть PR на GitHub в `main`.
3. Дождаться зелёного CI (Ruff Lint).
4. Получить один approval от второго разработчика.
5. Мерж — через Squash and merge.

Прямой push в `main` технически заблокирован — не пытайтесь обойти.
